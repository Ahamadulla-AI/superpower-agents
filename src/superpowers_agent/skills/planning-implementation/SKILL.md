# Planning Implementation

Use this skill only after the user approves the specification.

## Process

1. Inspect the repository structure, conventions, and relevant code before assigning files.
2. Split the work into small tasks with one clear outcome each and explicit dependencies.
3. For code changes, include how behavior will be verified and prefer a test-first sequence when tests are appropriate.
4. Keep tasks within the approved scope. Avoid speculative refactors and unrelated cleanup.
5. Check that the tasks collectively cover every acceptance criterion and can be completed in dependency order.
6. Present the plan for approval before implementation begins.

## Output

Provide numbered tasks with purpose, files or areas affected, steps, dependencies, and completion criteria. Flag risks or unresolved prerequisites.
