# Writing Specifications

Use this skill after the user has settled the design direction and before implementation planning.

## Process

1. Review the approved design and inspect relevant project context.
2. State the goal, user-visible behavior, constraints, and measurable acceptance criteria.
3. List non-goals to make scope boundaries clear.
4. Resolve contradictions against the user's latest instruction; call out any remaining decision that blocks implementation.
5. Present the specification for user review. Do not treat a generated specification as approval to implement.

## Output

Write a concise Markdown document with sections for Goal, Requirements, Constraints, Non-goals, and Acceptance Criteria. Make each criterion observable and testable.
