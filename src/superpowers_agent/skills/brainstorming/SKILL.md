# Brainstorming

Use this skill when a user brings an early feature or project idea and the intended behavior, audience, or constraints need clarification.

## Process

1. Read the relevant project files and identify existing conventions and constraints.
2. Ask up to three targeted questions that would change the design. Ask only what is still unknown.
3. Once enough is known, outline two or three viable approaches, including their tradeoffs and a recommendation.
4. Keep the scope tied to the user's goal. Record assumptions explicitly when they do not affect the core design.
5. Do not edit code during brainstorming. End with a concise design direction and ask the user to approve or correct it.

## Output

Summarize the problem, goals, constraints, open decisions, and recommended approach in plain language. Separate confirmed requirements from assumptions.
